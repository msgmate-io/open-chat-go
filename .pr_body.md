## Done in this push — item 3: per-workspace cgroup guard (`backend/sandboxpool/cgroup.go`)

`MaxWorkspaces` (default 8) is only a count bound: one noisy agent can starve its peers. A cgroup v2 slice now bounds each workspace of the pool, additively to the ci#546 network policy (same workspace UUID keys both):

- `cpu.max` / `cpu.weight` (default 1 core per workspace), `memory.max` / `memory.high` (default 2 GiB, soft limit below the hard one so a workspace is throttled before it is OOM-killed), and a published disk byte budget (64 MiB/s) bound per device through `io.max` (`MAJ:MIN rbps=.. wbps=..`, `CgroupIOMaxLine`) once the mount's device is known.
- Fail closed: `DetectCgroupHostSupport` requires a unified (`cgroup.controllers`) hierarchy with `cpu`/`memory`/`io`; a missing controller is a blocker and the pool refuses the workspace (`ErrWorkspaceCgroupUnavailable`) instead of handing out an unbounded slice, never a silent downgrade.
- The slice name is a hash of the workspace UUID (`wsc-<hash>.slice`, the UUID never becomes a path), so it is deterministic across a pool restart and disjoint between workspaces. The workspace reads its own slice and limits from `CODER_CGROUP_*` env (names and numbers only).
- Off by default (`OCI_MSGMATE_CODER_SANDBOX_WORKSPACE_CGROUP_GUARD=1` opts in); a non-boolean lever never enables an unconfigured bound and an unparseable limit falls back to the bounded default.
- `ResolveWorkspaceCgroupStatus` renders the guard for the admin surface (policy, host check, per-workspace slice, refusal reason) without creating anything; `(*PortAllocator).WorkspaceCgroups` follows the live leases and reports a refused workspace as a note instead of dropping it.
