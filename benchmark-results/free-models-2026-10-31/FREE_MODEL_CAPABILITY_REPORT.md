## Methodology

1. **Tests**: the all-tags set of `development/ci/sandbox_tests/*` as dispatched with `tags=""` on
   `private-sandbox-tests.yaml` (46 tests, grouped per the ticket's tag map). The image-attachment
   test is vision-gated and marked `n/a` for text-only models instead of failing them.
2. **Runner**: one `workflow_dispatch` per model with
   `opencode_provider=openrouter`, `opencode_model=<id>`, `target_ref=main`,
   `sandbox_interaction_timeout=900`, `sandbox_test_timeout=1800`; `run-tests` uses
   `SANDBOX_MAX_PARALLEL` (default 6) and each test retries once.
3. **Retries/timeouts**: pass = passed on attempt 1 or the single retry; timeout = exceeded the
   wall-clock budget; fail = capability failure after retries.
4. **Provider classification**: provider-side failures are classified by the ci#479 classifier
   (`provider_account`, `provider_unreachable`, …) and reported separately — a free-tier rate
   limit or credential error is not counted as a model capability result.
5. **Free-tier caveats**: `:free` models are rate-limited and intermittently unavailable; the
   cycles in this report are idempotent re-runs and each row notes the snapshot date. Provider
   errors are re-classifiable on re-run.
6. **Reproducibility**: exact dispatch inputs are in the ticket body; results TSVs are committed
   per model in this directory and regenerated by `build_free_results.sh` + `generate.sh`.
